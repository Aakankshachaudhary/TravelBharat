# TravelBharat – Design System

## 1. Design Philosophy

TravelBharat will use a clean, modern, informative and visually engaging design.

The interface should communicate:

- Exploration
- Trust
- Indian culture and heritage
- Simplicity
- Accessibility
- Professionalism

The design should avoid excessive decoration and prioritize usability.

---

## 3. Typography

The interface will use a clean sans-serif font.

### Heading Hierarchy

H1:
Large and prominent page titles.

H2:
Major section headings.

H3:
Card and subsection headings.

### Body Text

Body text should prioritize readability.

### Typography Guidelines

- Use consistent font weights.
- Avoid excessive uppercase text.
- Maintain readable line height.
- Keep paragraphs reasonably short.
- Use clear visual hierarchy.

---

## 4. Spacing System

The application will use a consistent spacing scale.

Base spacing units:

- 4px
- 8px
- 12px
- 16px
- 24px
- 32px
- 48px
- 64px

Spacing should be reused instead of introducing random values.

---

## 5. Layout

The application will use a responsive container system.

Desktop:
- Centered content
- Maximum readable width
- Multi-column layouts where appropriate

Tablet:
- Reduced columns
- Flexible spacing

Mobile:
- Single-column layouts
- Touch-friendly controls
- Simplified navigation

---

## 6. Buttons

### Primary Button

Used for the main action on a page.

Examples:

- Explore Destinations
- Search
- Add Destination
- Save Changes

### Secondary Button

Used for supporting actions.

Examples:

- View Details
- Cancel
- Clear Filters

### Destructive Button

Used for dangerous actions.

Examples:

- Delete Destination
- Delete State

Destructive actions should require appropriate confirmation.

---

## 7. Cards

Cards will be used for:

- States
- Cities
- Destinations
- Categories

Each card should have:

- Image where applicable
- Title
- Short supporting information
- Clear action
- Consistent spacing
- Consistent border radius

Cards should provide visual feedback when interactive.

---

## 8. Images

Destination images are an important part of the TravelBharat experience.

Images should:

- Use consistent aspect ratios
- Include meaningful alt text
- Be optimized for web usage
- Avoid unnecessary large file sizes
- Maintain good visual quality

Important destination images should visually communicate the location.

---

## 9. Navigation

The public navigation should remain simple.

Primary navigation:

- Home
- Explore India
- Destinations
- Categories
- About

The navigation should:

- Clearly indicate the current page
- Work on mobile devices
- Provide accessible controls
- Avoid unnecessary menu items

---

## 10. Forms

Forms should provide:

- Clear labels
- Appropriate input types
- Required field indication
- Validation feedback
- Helpful error messages
- Clear submit and cancel actions

Admin forms should be designed for efficient content management.

---

## 11. Search and Filters

Search should be easy to discover.

The search interface should support:

- Search input
- State filter
- City filter
- Category filter
- Clear filters
- Result count

Filters should remain understandable on mobile devices.

---

## 12. Loading States

The application should provide feedback while content is loading.

Possible patterns:

- Skeleton loaders
- Loading indicators
- Disabled actions during submission

The user should never be left wondering whether the application is working.

---

## 13. Empty States

Empty states should clearly explain when no content is available.

Examples:

- No destinations found
- No search results
- No destinations in this category

Where appropriate, provide an action such as:

- Clear filters
- Explore all destinations

---

## 14. Error States

Errors should be communicated clearly.

Examples:

- Unable to load destinations
- Something went wrong
- Destination not found
- Server unavailable

Error messages should avoid exposing technical implementation details to normal users.

---

## 15. Accessibility

The application will follow basic accessibility principles.

Requirements include:

- Semantic HTML
- Proper heading hierarchy
- Meaningful alt text
- Labels for form controls
- Keyboard navigation
- Visible focus states
- Accessible buttons
- Readable text
- Sufficient color contrast

---

## 16. Responsive Breakpoints

The design will support:

### Mobile

Up to approximately 767px.

### Tablet

Approximately 768px to 1023px.

### Desktop

1024px and above.

The exact layout will be flexible rather than relying only on fixed breakpoints.

---

## 17. Border Radius

A consistent radius system will be used.

Small:
6px

Medium:
10px

Large:
16px

Cards and major containers should use consistent corner treatment.

---

## 18. Shadows

Shadows should be subtle and used mainly to establish hierarchy.

Avoid excessive shadows.

Cards, dropdowns, modals and elevated navigation elements may use shadows when appropriate.

---

## 19. Interaction Principles

Interactive elements should provide clear feedback.

Examples:

- Hover state
- Focus state
- Active state
- Disabled state
- Loading state

Interactions should feel responsive without unnecessary animations.

---

## 20. Animation

Animations should be subtle and purposeful.

Use animation for:

- Navigation transitions
- Card hover feedback
- Modal appearance
- Loading feedback

Avoid excessive animation that distracts from tourism content.

---

## 21. Design Consistency

The same component should look and behave consistently throughout the application.

For example:

A DestinationCard used on the home page should maintain the same basic design when used on:

- State pages
- Search results
- Category pages
- Related destinations

---

## 22. Design Goals

The final interface should be:

- Professional
- Responsive
- Accessible
- Fast
- Consistent
- Easy to navigate
- Visually engaging
- Suitable for a real-world tourism platform
